  `useSyncExternalStore` because the generated version broke the `react-hooks/set-state-in-effect`
  rule.
- The `form` shadcn component does not exist in the `radix-nova` registry; forms will use React
  Hook Form + Zod with the `field` primitives (D-003).
- No database, no worker, no data layer yet — that is P0-2 onward.
- Chromium is installed for Playwright. Firefox and WebKit are not yet installed; P0-2 needs
  them for the cross-browser acceptance line (`pnpm exec playwright install firefox webkit`).
- Dark mode tokens exist in CSS but no theme toggle is wired (not in v1 scope until P6-5).
- GitNexus's vector extension is unavailable in this environment (exact-scan only for semantic
  search). Graph, full-text search and local embeddings all work.
- The GitNexus MCP server is also registered in the **global** OpenCode config by
  `gitnexus setup`; the project entry in `opencode.json` takes precedence. Remove the global
  one with `pnpm exec gitnexus uninstall` if it is unwanted.
- Playwright MCP pins its own Chromium build (`chrome-for-testing`), separate from the one
  `@playwright/test` uses. It is installed here; on a fresh machine run
  `pnpm exec playwright-mcp install-browser chrome-for-testing`.
- The third-party skills in `.claude/skills/` are **not** in the repository and never were:
  the history was rewritten before the first push and the directory is git-ignored. See
  D-015.
- The Content-Security-Policy in `public/_headers` is written but not yet exercised against a
  live worker and service worker. It must be verified in P0-6, once the SQLite worker and the
  offline cache exist. See D-017.

### T-002 — Commit message enforcement — **Done** (pending merge into `dev`)

**Acceptance:** the commitlint rules reject a bad message and accept a good one.

**What changed**

- Added `husky`, `@commitlint/cli`, `@commitlint/config-conventional` and `lint-staged`
  (D-019).
- `commitlint.config.js` enforces the `COMMIT_SYSTEM.md` rules: required scope from the
  allowlist, the nine allowed types, a 72-character subject, lowercase imperative subject, no
  trailing period, and the forbidden-subject list.
- `.husky/commit-msg` runs `commitlint --edit`; `.husky/pre-commit` runs `lint-staged`.
- `lint-staged` in `package.json` runs ESLint and Prettier on staged files.

**Results**

| Input                                                  | Expected | Got      |
| ------------------------------------------------------ | -------- | -------- |
| `feat(payments): add partial payment allocation`       | accepted | accepted |
| `fix(auth): reject expired refresh tokens`             | accepted | accepted |
| `feat: lots of things`                                 | rejected | rejected |
| `fixed stuff`                                          | rejected | rejected |
| `feat(nope): something`                                | rejected | rejected |
| 75-character subject                                   | rejected | rejected |
| trailing period / capitalised subject / uppercase type | rejected | rejected |

**Known gaps**

- Not signed (D-020).
- The hooks are local. CI does not run commitlint again; a commit that bypassed the hook with
  `--no-verify` would be caught only by `code-reviewer`. CI-only enforcement was an option the
  human did not choose.

### T-010 / P0-2 — sqlite-wasm worker spike — **Done in Chromium and Firefox; Safari open**

**Acceptance:** create a table, insert, reload, data persists; `exportBytes` and
`importBytes` round-trip; passes in Chrome, Firefox and Safari; findings in
`docs/DECISIONS.md`.

**What changed**

- `src/core/db/worker.ts` — the Worker owns the whole SQLite connection: sqlite-wasm with
  the `opfs-sahpool` VFS, `PRAGMA foreign_keys = ON`, and a Comlink API exposing `query`,
  `run`, `exportBytes` and `importBytes`. `tx` and repositories are P0-3.
- `src/core/db/client.ts` — the main-thread half: one Worker, wrapped with Comlink.
- `src/app/dev/DbSpikeHarness.tsx` — a small temporary harness at `/__db-spike`, removed in
  P0-3. It makes the acceptance line observable in a real browser.
- `e2e/sqlite-persistence.spec.ts` — three specs: persistence across reload, byte
  round-trip, and zero console errors / zero external requests.
- `playwright.config.ts` — added `firefox` and `webkit` projects.

**Results**

| Browser        | Persistence                       | Byte round-trip | Console/network clean |
| -------------- | --------------------------------- | --------------- | --------------------- |
| Chromium       | pass                              | pass            | pass                  |
| Firefox        | pass                              | pass            | pass                  |
| WebKit (Linux) | skipped — OPFS unavailable, D-023 | skipped         | skipped               |

`pnpm e2e`: **12 passed, 3 skipped**. `pnpm check` green.

**Known gaps**

- **Safari on macOS is not verified.** The Linux WebKit build has no working OPFS (D-023).
  P0-2's cross-browser acceptance is only partly met and the phase cannot be declared
  complete until a macOS run happens.
- No COOP/COEP headers were needed, which confirms the locked VFS choice.
- The harness calls the spike client directly; it is a test tool, not product UI, and is
  deleted in P0-3.
- One WebKit worker crashed with SIGSEGV in a single parallel run; a rerun passed.

**Next:** T-011, the full `Db` client with a serialized queue and `tx`, then T-012, the
`better-sqlite3` test double. Ask the human for a macOS runner before closing P0-2.
