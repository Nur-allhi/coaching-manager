# Conventions

House rules for writing code in this repository. They exist so that eleven modules look like
one codebase.

## 1. TypeScript

- `strict`, plus `noUncheckedIndexedAccess`, `noImplicitOverride`, `noUnusedLocals`,
  `noUnusedParameters`, `erasableSyntaxOnly`, `noFallthroughCasesInSwitch`.
- `erasableSyntaxOnly` means **no `enum`** and **no constructor parameter properties**. Use
  union types of string literals and plain objects.
- `verbatimModuleSyntax` is on: type-only imports must use `import type`.
- Prefer `type` over `interface` for unions and mapped shapes; use `interface` only for
  extensible object contracts.
- Money is `number` (integer paisa). Never `number` for a decimal amount.
- Optional properties are `prop?: T` and are omitted, not set to `undefined`, when absent.

## 2. Naming

| Thing                  | Convention      | Example                                      |
| ---------------------- | --------------- | -------------------------------------------- |
| Files and folders      | kebab-case      | `money/format.ts`, `payment-allocations.ts`  |
| Components             | PascalCase      | `PaymentReceipt`, `AttendanceGrid`           |
| Hooks                  | `useX`          | `useOptimisticMutation`, `useStudentFilters` |
| Types and interfaces   | PascalCase      | `StudentRow`, `ChargeKind`                   |
| Constants              | camelCase       | `defaultGradingScale`                        |
| SQL tables and columns | snake_case      | `academic_years`, `amount_minor`             |
| i18n keys              | dotted path     | `payments.receipt.title`                     |
| Environment variables  | SCREAMING_SNAKE | `GITNEXUS_MCP_AUTH_TOKEN`                    |

Strings that identify a fixed set of values are union types, not enums:

```ts
export type ChargeKind = 'admission' | 'monthly' | 'other'
export type AttendanceStatus = 'P' | 'A' | 'L' | 'E'
export type PaymentMethod = 'cash' | 'bank' | 'bkash' | 'nagad' | 'other'
```

## 3. Money

**Money is never a float.** All amounts are integer paisa in `*_minor` columns.

- Store: `amount_minor INTEGER NOT NULL`.
- Read and write through `src/core/money`. Never do arithmetic inline in a component.
- Format for display: whole taka unless the paisa part is non-zero.
- Percent discounts round **exactly once**, at the end, to the nearest paisa, and the rule is
  unit-tested. Never round per line item and never round a percentage.
- Totals are computed from integer sums. A `SUM()` over an INTEGER column is exact.
- A receipt amount, a due amount and a balance are all integers. No epsilon comparisons.

Helpers to provide in `src/core/money` (P0-5):

```ts
formatMinor(amountMinor: number, locale?: string): string
parseToMinor(input: string): number
applyPercentDiscount(amountMinor: number, percent: number): number
sumMinor(values: number[]): number
```

## 4. Dates and time

- Stored: dates as `YYYY-MM-DD`, months as `YYYY-MM`, timestamps as epoch milliseconds (UTC).
- Display timezone is **Asia/Dhaka**. Convert at the display boundary, never in storage.
- Use `date-fns` for arithmetic. Do not hand-roll date maths.
- "Today" for the front desk means today in Dhaka, not the machine's timezone.
- Month keys are always zero-padded: `2026-01`, never `2026-1`.

## 5. IDs

- UUIDv7 via the `uuidv7` package. Time-sortable and sync-ready.
- One `newId()` helper in `src/core/db`, never `crypto.randomUUID()` scattered around.
- Human-facing identifiers are separate from primary keys:
  - student number `YYYY-0001` by admission year,
  - receipt number `R-YYYY-000001`, sequential, never reused, never changed by an edit.
- Sequential numbers come from the `counters` table, allocated inside the same transaction as
  the row that uses them, so they stay gapless.

## 6. Modules and layering

Allowed direction of dependency:

```
UI  →  services  →  repositories  →  Db client  →  Worker
```

Rules:

- A module may import its own internals freely.
- A module imports another module **only** through that module's `index.ts`.
- Read-model modules (`dashboard`, `reports`, `leaderboard`) may query any table, but only from
  files in their own `queries/` folder.
- `src/core/*` never imports from `src/modules/*`.
- `src/components/ui/*` is generated by the shadcn CLI and is exempt from lint and formatting
  rules. Never hand-edit it; run `pnpm dlx shadcn@latest add <component>` instead.

## 7. Repositories

Repositories are the only place SQL is written.

```ts
export async function update(id: string, patch: Patch, expectedVersion: number) {
  // UPDATE ... SET ..., version = version + 1, updated_at = ?
  // WHERE id = ? AND version = ? AND deleted_at IS NULL
  // changes === 0 means either "not found" or "version conflict" — distinguish them.
}
```

- Every statement is parameterized. No string concatenation into SQL, ever. Identifiers
  (table and column names) are the only thing that may be interpolated, and they come from
  code, not from user input.
- Every list query filters `deleted_at IS NULL` unless it is explicitly a trash query.
- Every write bumps `version` and `updated_at`.
- Every write writes an `audit_log` row in the same transaction.

## 8. Services

Services hold the business rules and are the boundary the UI talks to.

- Validate every input with Zod on the way in. The UI validates too, but the service is the
  authority.
- Check permissions here, not only in the UI.
- Throw typed errors the UI can render. A refusal to delete a parent with children must carry
  a message the admin can read.
- A service that mutates more than one row does it in one `db.tx()`.

## 9. Errors

- No raw `Error` with a hard-coded English string for anything user-visible.
- Define a small typed error set in the owning module; map it to an i18n key at the UI edge.
- A version conflict is its own error kind, because the UI responds differently: show the newer
  values and offer a reload.
- Never swallow an error. If a failure cannot be handled, let it reach the error boundary.

## 10. React

- Function components only. No class components.
- `React.ComponentProps<'button'>` for prop types, never a hand-written interface that drifts.
- Server state lives in TanStack Query. Local component state stays local. Zustand is only for
  tiny cross-component UI state.
- Every list that can grow past a screen uses TanStack Table for columns and TanStack Virtual
  for rows.
- Every async surface renders four states: loading, empty, error, and content. Empty states
  explain what to do next, they are not a blank box.
- Forms use React Hook Form with a Zod resolver. On a version conflict, show the newer values
  and offer a reload; never silently overwrite.
- Guard unsaved changes on every form (the error boundary must never lose input).
- Keyboard first: arrow keys, Enter and Tab work in the marks and attendance grids.

## 11. i18n

- **Every** user-visible string goes through an i18next key. No hard-coded text in
  components.
- Keys are namespaced by module: `payments.form.amount`, `students.list.empty`.
- The Bangla translations must be reviewed by a human, not machine-generated and shipped.
- Optional Bangla digits via `Intl.NumberFormat('bn-BD')`, behind a setting.
- Dates and numbers format through the active locale, not through hard-coded patterns.

## 12. Accessibility

Not optional, and it is part of the definition of done.

- Every input has a label. Placeholders are not labels.
- Visible focus on every interactive element; the base stylesheet already provides it.
- Contrast AA.
- `prefers-reduced-motion` is respected (the base stylesheet already disables animation).
- The layout works at phone width and at tablet width; a tablet is what sits on the front
  desk.
- Interactive elements are real `<button>` and `<a>` elements, not styled `<div>`s.

## 13. Comments and commits

- Comment the **why**, never the what. The code says what it does.
- A comment that explains a rule cites the rule: "see PLAN §7.3".
- One task per commit. Message format: `feat(payments): P3-2 record payment`.
- Commit body explains the why and any deviation.

## 14. Formatting and linting

- Prettier owns formatting. Do not hand-align anything.
- ESLint owns correctness rules. `@typescript-eslint/consistent-type-imports` is on.
- `no-console` is a warning; only `console.warn` and `console.error` are allowed. Use the
  toast/logger instead of `console.log`.
- Run `pnpm format` before you commit; `pnpm check` before you propose a commit.
